# 事故复盘：2026-09-18 支付超时导致订单接口大量 500

## 概要

2026-09-18 20:05 至 20:47，订单创建接口错误率最高达到 23%，持续 42 分钟，定级 P1。直接原因是支付网关响应变慢，订单服务在数据库事务内同步调用支付网关，导致数据库连接被长时间占用，最终连接池耗尽，接口返回 HTTP 500 和 ORD-5003。

## 时间线

- 20:05 告警：order-service 5xx 比例超过 5%。
- 20:12 值班工程师发现日志中大量 ERR_PAY_TIMEOUT 和 "Connection is not available"。
- 20:20 确认支付网关 P99 延迟从 300ms 升至 4.5 秒。
- 20:31 手动打开支付熔断器，新订单改为异步支付确认。
- 20:47 错误率恢复正常。

## 根因

1. 在事务内调用远程支付网关（违反连接池调优指南的建议）。
2. 熔断器阈值过高，没有自动打开。
3. 重试策略没有退避，客户端重试放大了流量，形成重试风暴。

## 改进措施

- 支付调用移出数据库事务（负责人：订单平台组，已在 v2.3.2 完成）。
- 熔断阈值调整为 10 秒内失败率 50%。
- 客户端 SDK 增加指数退避和最多 3 次重试。
- 新增告警：连接池活跃连接数超过 80% 持续 2 分钟。
